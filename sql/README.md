# SQL 脚本说明

> **复现方式：在空数据库中执行。** 本目录脚本的复现标准是——**删掉数据库、按下面的顺序一次性跑完，得到相同的表结构与样例数据**。不是在已有库上"不报错地再跑一遍"。
> 脚本用 T-SQL（含 `GO`），不适用于 MySQL。

## 当前文件（阶段一·第 3 周）

| 文件 | 用途 | 可重跑？ |
| --- | --- | --- |
| `00-drop.sql` | **删库**——复现的起点，使库回到"不存在" | 是（幂等：库不存在则跳过） |
| `00-create.sql` | 建库（`BubbleTeaShop`，`COLLATE Chinese_PRC_CI_AS`） | **否**——库已存在会报错并提示先跑 `00-drop.sql` |
| `01-schema.sql` | 建表，含主码 / 候选码 / 外码 / 检查约束 | **否**——要求空库；非空库会报"对象已存在" |
| `02-seed.sql` | 装载虚构样例数据 | **否**——重复插会撞主码 / 候选码 |

> **为什么删库是独立文件而不是塞进 `00-create.sql`**：`01-schema.sql`、`02-seed.sql` **都只能在空库上跑**（表已存在会报错、数据重复会撞约束），所以复现必须从"库不存在"出发。但**删库是破坏性动作，不该藏在"建库"脚本里**被顺手执行——它需要使用者显式触发。拆开后：
> - 复现 = `00-drop.sql` → 余下按顺序跑；起点明确，且每次结果相同。
> - 误跑代价受控：跑 `00-create.sql` 只会报错提示，不会毁掉现有库。
>
> 阶段一（1—4 周）不涉及真实数据，删库无损失；`00-drop.sql` 会先 `SET SINGLE_USER WITH ROLLBACK IMMEDIATE` 断开占用连接再删。

## 执行顺序（复现：从删库开始）

```powershell
# 复现起点：删掉旧库（幂等，库不存在也能跑）
sqlcmd -S '.\SQLEXPRESS' -E -C -b -f 65001 -i sql/00-drop.sql
# ①—④ 建库→建表→装载：每次复现都完整重跑
sqlcmd -S '.\SQLEXPRESS' -E -C -b -f 65001 -i sql/00-create.sql
sqlcmd -S '.\SQLEXPRESS' -E -C -b -f 65001 -i sql/01-schema.sql
sqlcmd -S '.\SQLEXPRESS' -E -C -b -f 65001 -i sql/02-seed.sql
```

**复现验证 = 把上面整段从头再跑一次**（首行 `00-drop.sql` 已清空旧库，故无需手工清理），比对两次得到的表结构与数据是否一致。不要求"第二次也不报错地跳过建表"——要求"第二次得到同样的库"。

> `-f 65001` 指定 UTF-8 编码，避免中文乱码；实例名（`.\SQLEXPRESS`）按本机环境修改。
> 若报 SSL 证书不受信任，加 `-C` 信任自签证书（ODBC Driver 18 默认强制加密）。
