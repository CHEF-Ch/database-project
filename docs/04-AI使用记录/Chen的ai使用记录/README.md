> 课程要求"须保留 AI 输出与人工修改内容"。以下为 AI 给出的、经核对后**被纠正**的判断，保留以佐证人工判断过程。

| # | AI 的说法 | 问题 | 我的处理 |

| 1 | "配送费属代收转付，门店代平台收取后转交" | 平台单由平台统一收全部款项，门店从未经手，不存在"转付" | 指出后改为"配送费不进门店账目，仅为记录字段" |

### 候选答案与取舍

| 概念 | 候选方案 | 最终选定 | 为什么 |
| --- | --- | --- | --- |
| 原料 vs 商品 | 按成品"卖一杯扣一杯" | 原料级库存，按配方 + 加料扣料 | 支撑缺料判断与补货触发 |
| 默认小料 vs 加料 | 所有小料都额外收费 | 配方内小料算商品价，加料额外收费 + 扣料 | 避免重复收费 / 扣料 |
| 平台抽成 vs 门店实收 | 只记平台订单金额 | 记抽成比例 + 额，门店实收 = 商品金额 − 抽成额 | 对账、算真实营业额 |
| 充值收入 vs 销售额 | 充值计为销售额 | 充值非销售；余额消费不再计分 | 避免重复计分、口径混乱 |
| 门店单号 vs 平台单号 | 直接用平台单号作主键 | 门店统一连续编号作主键，平台单号独立唯一防重 | 各来源统一；平台单号用于对账与幂等 |
| 状态机 | 平台单也走 PENDING | 平台单预收款、PAID 起步无 PENDING；共 6 状态 | 平台预收款，门店收到即已支付 |
| **保质期建模** | **A 不做 / C 完整批次（批次表、FIFO、跨批扣料）/ D 保质期天数 + 临期视图** | **D**（阶段一）；C 留阶段二评估 | D 零侵入、成本低，且其字段在 C 中可原样保留，升级不返工；奶茶店原料周转快，批次级追溯非必需 |
| **库存动作划分** | 单一"预留"概念 / 行业"预占·确认·释放"三动作 | 三动作 | 拆分后方能明确各动作改动哪些字段、是否写流水，为第 3 周扣料与第 4 周约束提供落点 |
| **平台单扣料时机** | 接单预占、制作时转实耗 / 接单即确认耗用 | 接单即确认耗用 | 平台已预收款、无待支付保护期，预占无意义；避免原料被长期占用于排队期 |

### 候选答案与取舍

| 概念 | 候选方案 | 最终选定 | 为什么 |
| --- | --- | --- | --- |
| **补货单粒度** | 单表（含"原料、数量"列）/ 拆单头 + 明细 | 拆两张 | 业务上一张单能补多样原料；不拆则"同一张单两行写两家供应商"无约束可拦 |
| **平台信息归属** | 并进 `shop_order`（4 个可空列）/ 独立子表 | 独立子表，主码 = `order_id` 兼外码 | `docs/01` §4.5 已写"挂平台订单信息**子表**"；且到店单是多数，并进去会让多数行带 4 个 NULL。主码即外码则 1:0..1 天然成立，无需额外 `UQ` |
| **券的粒度** | 一张表（规则 + 持券）/ 拆两张 | 拆两张 | 券规则由店长低频改、持券状态随每笔订单改——**变化时机不同**；且 `UNUSED/USED` 是持券的状态，放一张表会出现"规则的状态是 USED"这种怪话 |
| **原料与加料** | 两张表 / 合并一张用 `kind` 区分 | 合并 | 珍珠既是原料又是加料，是**同一实体的两种角色**；分开会让同一袋珍珠有两条记录、两份库存，扣料时不知该扣哪条 |
| **加料单价落点** | 存 `item_material`（原料级）/ 存 `item_addon_option`（商品-原料对） | 存 `item_addon_option` | `addon_price` 函数依赖于 `(product_id, material_id)` **组合**，不是任一子边。珍珠在珍珠奶茶里是配方料（不收费）、在四季春茶里是加料（+2 元）——一单即可反证"单价由原料唯一决定" |
| **配方是否挂价** | 挂价（商品的成本构成）/ 不挂 | 不挂，只有 `product_id`/`material_id`/`qty` | **售价 ≠ 成本**。配方记的是"用多少料"；原料采购成本未进库（`docs/01` §6），无成本价可挂；商品价是商品级的一个数（含配方内小料） |
| **会员积分/余额** | 纯流水（用时 `SUM`）/ 快照 + 流水双写 | **快照 + 流水** | 唯一硬收益是第 4 周能写 `CHECK (balance >= 0)`，把"余额不能透支"**拦住**；纯流水只能事后发现。一致性由第 3 周事务承担 |
| **原料现存量/预留量** | 同上 | **快照 + 流水**（无商量余地） | `docs/01` 三处一致指向"存"：§5 列出字段、§3 主流程的操作对象就是它们、§8 预告 `CHECK (reserved_qty <= stock_qty)`——**该约束是两个快照之间的关系，无快照即无约束** |
| **订单状态历史** | 建 `order_status_log` / 只存当前值 | 只存当前值 | ① 状态**转移规则**不是 `CHECK` 能表达的对象（`CHECK` 只看单行、看不到上一状态），故流水表**不为约束服务**；② 状态是终态一次性的，快照无性能收益；③ 追溯由时间字段 + 各流水表承担。代价与升级条件已写明 |
