### 候选答案与取舍

| 决策点 | 候选方案 | 最终选定 | 为什么 |
| --- | --- | --- | --- |
| 杯型归属 | 杯型作为订单行可选维度（需商品-杯型价格档结构） | 杯型是商品固有属性：不同杯型 = 不同商品不同价；`order_item.size` 留作快照 | 售价天然挂商品、无价格档结构，复杂度最低，符合 `docs/01` §5 字面 |
| 门店订单号生成 | `IDENTITY` / `SEQUENCE`+每日重置 / 本阶段手工 | 本阶段手工（`YYYYMMDD`+4 位当日序号） | 跨天归零序号无法用纯 DDL 表达；自动生成留阶段三 |
| 加料扣料量来源 | 挂 `item_material`（原料的加料份量） | 挂 `item_addon_option`（新增 `addon_qty` 列） | 与加料单价同处、函数依赖于 `(商品,加料)` 组合主码，和 `item_recipe.qty` 对称 |
| 流水/持券表主键 | 全部字母前缀业务号 / 全部 `IDENTITY` | 分流：主数据/单据用 `CHAR` 业务号，流水/持券用 `BIGINT IDENTITY` | 单据需人读，日志型主键只作行标识；统一业务号会让"券"与"会员"争抢字母 `C` |
| 幂等键落点 | 靠应用层事务保证 / 字段唯一约束 | 三处建 `UNIQUE`：平台单号、支付流水号、充值外部参考号（均允许多 NULL） | 幂等是核心规则，唯一约束在入库层就挡重复，比应用层保证更稳 |
| 订单金额字段 | 派生（明细求和） | 快照三列：`item_subtotal`/`coupon_discount`/`total_amount` | `docs/01` §4.4 要求券优惠快照；历史订单不随调价/改券变化 |
| 退款落点 | 独立退款表 | `shop_order` 加 `refund_amount`/`refund_at` 两可空列 | 整单退款一笔一单，无需独立表；积分/余额冲正走各自流水表 |
| 券有效期 | 领取后 N 天（持券级） | 规则级固定起止日期 `valid_from`/`valid_to` | 最简单，无持券级有效期复制 |
