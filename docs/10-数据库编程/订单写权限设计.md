# R07 订单写权限设计

现有 Flask 会话完成顾客本人订单、收银收款、制作状态流转和店长退款的授权。数据库的 `role_app` 由服务端持有，当前仍具备业务表直接写权限。它不能用来证明请求者身份。直接连接数据库时，信任边界是 SQL 登录和其持有的权限。

计划按下单、支付、取消、退款拆分执行入口。退款由独立的服务端数据库身份执行，普通订单写入账户只得到各自需要的过程执行权。过程仍要校验订单状态、原子更新和重试行为。应用负责用已认证的会话校验操作者、所属订单及其权限；前端传入的角色字段不参与授权。复核时确认过程内部的表权限来自适当的执行上下文或所有权链，并测试同名角色参数无法扩大数据库账户的执行权限。

实施顺序：

1. 在独立验证库增加过程执行授权，接线并验证下单、支付、取消、退款与库存流水。
2. 将应用直写表的权限移除，与 R06 的真提交、回滚和并发实验一起验证。
3. 验收矩阵覆盖正常执行、普通账户直接改表、普通账户调用退款、越权应用请求以及 DDL/GRANT 权限。用不同 SQL 登录验证每个负例，并核对失败后库存、订单和流水不变。

第十周交付设计。授权切换及最终验收依赖 R03 和 R06。
