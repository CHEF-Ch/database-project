## 一、基线

## 三、统一口径（本次定稿）

1. **销售时间字段**（D1）：一律用 `shop_order.created_at`（下单时间），按 `CAST(created_at AS date)` 落在
   闭区间 `[date_from, date_to]`，**结束日期包含当日**（与 S06 口径一致）。
2. **已售出状态**（D2）：销量/销售额只算 `PAID`、`MAKING`、`COMPLETED` 三态；`REFUNDED` 不计销量/销售额，
   退款额单独统计；`PENDING`/`CANCELLED` 不计。
3. **金额口径**（D3）：订单级销售额 = `total_amount`（券后实收）；商品销售明细金额 = `qty × unit_price`
   （成交价快照、券前，**优惠不摊到单品**）；销量 = `SUM(order_item.qty)`；订单数 = `COUNT(DISTINCT order_id)`。
4. **补货量**（D4）：`max(0, safety_stock − stock_qty)`；`stock_qty ≥ safety_stock` 时为 0；不新加「目标库存」字段。
5. **折扣**（D5）：仅满减 `FULL_REDUCTION`（满 `threshold_amount` 减 `discount_amount`），函数只做纯计算、
   舍入 2 位；**历史快照沿用** `shop_order.coupon_discount / total_amount` 与 `order_item.unit_price`，函数不重算历史。
6. **事务边界**（D6）：过程/函数**不做 `COMMIT`/`ROLLBACK`**，由调用方（业务层→DAO）控制事务；业务失败用
   `THROW` 抛错，不静默吞掉。
7. **授权**（D7）：写过程授权给 `role_app`（写事务账户）；只读函数授权给需要查询的角色
   （`role_manager` / `role_cashier` / `role_stock`），具体矩阵到 ⑤ 应用整合时定稿。
8. **替换范围**（D8）：见第五节；**不保留两套写入**（过程成为唯一写入口，Python 里对应 SQL 移除）。

## 四、对象接口

### P1 `dbo.usp_sale_statistics` —— 销售统计过程

```sql
CREATE PROC dbo.usp_sale_statistics
    @date_from    DATE,
    @date_to      DATE,
    @order_count  INT           OUTPUT,   -- 订单数
    @sold_qty     INT           OUTPUT,   -- 销量（杯）
    @sales_amount DECIMAL(10,2) OUTPUT,   -- 销售额（券后实收）
    @refund_amount DECIMAL(10,2) OUTPUT   -- 退款额（区间内 REFUNDED 单）
AS ...
```

- 返回一个结果集：**商品销售明细**（`product_id, product_name, size, order_count, sold_qty, gross_amount`），
  复用 F2 `fn_sales_summary`（见下），避免同一份统计逻辑写两遍。
- 校验：`@date_from`/`@date_to` 非空且 `@date_from <= @date_to`；非法抛错。
- 无销售区间：三个输出为 0，明细结果集为空（不抛错）。
- 口径：订单数 = 状态 ∈ {PAID, MAKING, COMPLETED} 且下单日在区间内的 `COUNT(DISTINCT order_id)`；
  销售额 = 同口径 `SUM(total_amount)`；退款额 = 状态 = REFUNDED 且下单日在区间内的 `SUM(refund_amount)`。

### P2 `dbo.usp_adjust_stock` —— 库存调整过程

```sql
CREATE PROC dbo.usp_adjust_stock
    @material_id CHAR(8),        -- 原料编号
    @delta       DECIMAL(10,2),  -- 调整量（正增负减）
    @reason      VARCHAR(10),    -- GAIN / SHORT / LOSS
    @employee_id CHAR(8)         -- 经办员工
AS ...
```

- 校验：`@delta ≠ 0`；`@reason ∈ {GAIN, SHORT, LOSS}`；`GAIN` 要求 `@delta > 0`，`SHORT`/`LOSS` 要求 `@delta < 0`；
  原料存在（不存在抛"原料不存在"）。
- 写入（同一过程内、不提交）：
  - 条件更新 `item_material`：`stock_qty = stock_qty + @delta`，且 `stock_qty + @delta >= 0`
    且 `stock_qty + @delta >= reserved_qty`；命中 0 行 → `THROW`（调整后库存不足或低于预占量）。
  - 写一条 `inv_stock_log`（`log_type = @reason`，`qty = ABS(@delta)`，`employee_id`，
    `order_id`/`restock_id` 为 NULL）。
- 替换 `app/dao/inventory.adjust_stock_with_log`；service 层的参数校验与角色判断保留（`inventory.adjust`）。

### F1 `dbo.fn_replenish_qty` —— 补货量函数（标量）

```sql
CREATE FUNCTION dbo.fn_replenish_qty(@material_id CHAR(8)) RETURNS DECIMAL(10,2)
```

- 原料不存在 → 返回 `NULL`（由调用方决定如何提示）；否则返回 `max(0, safety_stock − stock_qty)`。
- 达标（`stock_qty ≥ safety_stock`）→ 0；非负。

### F2 `dbo.fn_sales_summary` —— 销售汇总表值函数（内联 TVF）

```sql
CREATE FUNCTION dbo.fn_sales_summary(@date_from DATE, @date_to DATE)
RETURNS TABLE AS RETURN ( ... )
```

- 返回列：`product_id, product_name, size, order_count, sold_qty, gross_amount`（与 P1 明细同口径）。
- 状态口径同 D2；`order_count = COUNT(DISTINCT order_id)`、`sold_qty = SUM(qty)`、
  `gross_amount = SUM(qty * unit_price)`。
- 可被 `SELECT ... FROM dbo.fn_sales_summary(...)` 直接调用/JOIN；是 P1 明细的复用核心。

### F3 `dbo.fn_discount` —— 折扣函数（标量）

```sql
CREATE FUNCTION dbo.fn_discount(
    @subtotal         DECIMAL(10,2),  -- 券前金额
    @threshold_amount DECIMAL(10,2),  -- 满 X
    @discount_amount  DECIMAL(10,2)   -- 减 Y
) RETURNS DECIMAL(10,2)
```

- 纯计算：`@subtotal >= @threshold_amount` → 返回 `@discount_amount`，否则返回 0；结果舍入 2 位。
- **不查表、不校验券归属/状态/有效期**：这些留在 `order_service`（替换 `_apply_coupon` 的金额部分，
  校验与锁券逻辑不动）。
- 历史快照：不重算历史订单，快照由 `shop_order.coupon_discount`/`total_amount` 承载（D5）。

## 七、待定（留给 ②③ 实现时细化）

1. P1 是否纳入平台单佣金/配送费：当前口径只算 `total_amount`（实收），不含平台抽成（符合"销售额=实收"）。
2. 销售统计的「商品销售」是否要区分到店/平台渠道：本设计不区分，按全渠道汇总；如讲解要求分渠道，② 再扩展。
3. F3 是否另加 `fn_discount_by_rule(rule_id, subtotal)` 变体（函数内查券规则表）：当前定为纯参数化、
   查表留在 service；如需"函数独立可用"再补变体。
