# 功能补全与重构设计

既有业务、对象接口、日期、退款、折扣、库存调整及补货建议口径见 [第十周过程与函数设计](过程与函数设计.md)。v1.0 结构和数据取证见 `result/第10周-①基线核对.txt`，角色及受限登录矩阵见 `result/第7周-①受限登录验证-20261122.txt`。

## 首个迁移范围

- 使用 v1.0 副本部署两过程、三函数、授权和版本标记。沿用 v1.0 表列、约束和索引。
- 库存和配方用量沿用原料的 `unit`。同一原料的库存、安全库存、预占、调整量和流水使用同一单位。
- 统计和补货建议为只读。库存调整过程更新库存并写一条业务流水，调用者拥有事务提交和回滚职责。现有应用在第十周⑤切换调用路径时移除对应旧写入。
- 销售统计和汇总由店长查询；库存员和店长可计算补货建议；折扣计算授权应用写账户和收银员；库存调整过程授权应用写账户。应用调用前仍需校验业务角色。
- 第十一周触发器的审计记录采用独立职责，现有库存业务流水由所属写入路径维护。订单完成及并发事务随后分增量交付。
- R02 是独立结构增量。新订单保存基础配方和加料的合计耗用，支付和取消读取该记录。先盘点存量 PENDING 单并登记可核对的耗用依据及处置方案；当前聚合预占量无法证明各历史订单的用量，待核对后才能迁移旧单。

## 部署与恢复

1. 对 v1.0 做 `COPY_ONLY` 完整备份并恢复到单独的目标库。保留来源备份和源库，先核对 v1.0 指纹与授权。
2. 在仓库根目录执行迁移，显式指定副本库名。

   ```powershell
   sqlcmd -S '.\SQLEXPRESS' -E -C -b -f 65001 -d <v2数据库名> -i sql/migration_v2_0.sql
   sqlcmd -S '.\SQLEXPRESS' -E -C -b -f 65001 -d <v2数据库名> -i scripts/v2_migration_test.sql
   sqlcmd -S '.\SQLEXPRESS' -E -C -b -f 65001 -d <v2数据库名> -i scripts/week10_objects_test.sql
   ```

3. 五个对象、授权和版本标记在同一个事务内生效。脚本失败后 SQLCMD 退出，未提交的 DDL 由服务器回滚。对象定义可以重复部署。
4. 部署后核对版本标记、健康检查及对象测试。若已提交的迁移需撤回，把应用连接切回保留的 v1.0 库或从备份还原到新库。若部署后已有业务写入，恢复前先核对需保留的数据。

### 业务库历史订单

快照按订单和原料存储总量，下单与库存变更在同一事务写入。应用账户有读取和插入权限，店长有读取权限。支付和取消使用快照，并保留既有订单锁和幂等规则。

上线前用下面的查询登记缺少快照的历史待支付单。逐单以当时的配方和加料记录或其他可核验凭证确认用量，并对照同一原料的合计预占做复核。经复核批准后，由数据库维护者在同一事务中锁定订单并写入完整快照。缺少凭证时保留待人工处理；当前配方和合计预占都无法证明单笔订单的历史用量。页面会在缺少快照时拒绝支付和取消。

```sql
SELECT o.order_id, o.created_at
FROM dbo.shop_order AS o
WHERE o.order_status = 'PENDING'
  AND NOT EXISTS (
      SELECT 1 FROM dbo.order_material_usage AS u WHERE u.order_id = o.order_id
  )
ORDER BY o.order_id;
```

## v2 应用接线

库存页调整经应用角色校验后，由应用写账户调用 `usp_adjust_stock`。订单的优惠额调用 `fn_discount`，归属、有效期、门槛提示和锁券仍由订单业务层处理。

店长可以调用 `GET /api/reports/sales?date_from=2026-09-01&date_to=2026-09-30`。接口调用 `usp_sale_statistics`，返回订单数、杯数、实收、退款和商品汇总。结束日期包含当日。旧统计视图仍用于前期交付和历史口径核对。

将 `DB_NAME` 指向 v2 验证库并运行 `python scripts/week10_app_test.py`，可复跑应用端统计、权限、库存和折扣验证。
