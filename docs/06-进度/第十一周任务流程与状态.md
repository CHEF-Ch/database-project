## 四、本周约束与待定事项

1. **按集合处理**：触发器一次可能处理多行，不得用一个变量保存一行后替代全集检查，也不能只验证单行成功。
2. **避免重复写入**：现有订单包含预占、支付实扣和后续状态流转，完成触发器须适配真实时点，不得再次扣库或与过程、DAO 重复写流水。
3. **操作人可追溯**：库存为原料级，共享数据库登录不能直接当作业务员工，须设计可靠传递方式。
4. **窗口范围明确**：最近 3 行不等于最近 3 个自然日；累计值明确排序和并列处理；先聚合再开窗口时说明输入与输出粒度。

| 待定项 | 需要确定的内容 | 定稿位置 / 时点 |
| --- | --- | --- |
| 审计存储 | 复用 `inv_stock_log` 或独立审计表；前后值字段；哪些库存字段变化要记录；如何消除原流水双写 | 设计说明 / ① |
| 事件与人员 | 插入、修改、删除的具体处理；业务员工如何传入；缺失操作人的处理 | 设计说明 / ① |
| 完成规则 | 各项检查与当前状态机的对应；重复完成与修改其他字段的区别；库存检查不能造成再次扣减 | 设计说明 / ① |
| 统计口径 | 承接第十周日期、销售、退款约定；排名指标、累计排序、最近 3 天/笔/月的窗口选择及无销售日期处理 | 设计说明 / ① |

## 五、验收要点

- 两个触发器自动执行，正常成功、非法拒绝，单行与多行均有证据。
- 混合合法非法行失败后无部分提交，被回滚操作不留下已提交的审计或其他半成品。
- 审计前后值、差量、类型和人员正确，不重复产生业务流水。
- 三类窗口查询各一条，业务含义、排序及窗口清楚，有手算预期与实际对照。
- 启用触发器后应用流程、权限和异常反馈仍正常；第二人复核通过后再改已完成。
