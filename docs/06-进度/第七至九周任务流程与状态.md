## 四、分层职责与检查口径

| 层 | 负责内容 | 不应承担的职责 |
| --- | --- | --- |
| 页面层 | 接收请求、表单基础校验、展示数据和友好提示 | 不直接连接 SQL Server，不拼接 SQL，不决定数据库权限 |
| 业务层 | 业务规则、角色判断、事务边界、统一错误转换 | 不把原始数据库异常直接返回前端 |
| 数据访问层 | 参数化 SQL、连接/参数/事务/资源管理、结果映射 | 不接收页面模板逻辑，不把用户输入拼进 SQL |
| 数据库层 | 表、约束、视图、数据和数据库账户权限 | 不依赖页面隐藏按钮保证安全 |

至少准备两条可说明的调用链：

```text
查询：页面请求 → Controller/API → Service → DAO 参数化 SELECT → SQL Server → 结果映射 → 统一响应 → 页面
修改：页面提交 → Controller/API → Service 校验角色与业务规则 → DAO 参数化写入 → 事务提交/回滚 → 统一响应 → 页面
```

## 六、验收要点

1. **可复现**：其他成员能从空环境按 README 配置数据库连接、安装依赖、启动应用并完成登录和核心流程；配置中的密码等敏感信息使用示例或环境变量。
2. **分层可解释**：能指出页面、业务、数据访问和数据库层的文件/模块，并说明一条查询、一条修改分别经过哪些层。
3. **参数化与资源管理**：所有用户输入都经过类型、长度、范围和必填校验，SQL 使用参数绑定；连接、游标和事务在成功、失败两条路径都正确释放或回滚。
4. **业务事务一致**：创建订单时，订单、订单明细和库存扣减必须按同一业务事务处理；库存不足、约束冲突或中途异常时不能留下半条订单。
5. **权限一致**：店员、顾客及扩展角色的操作差异有页面展示、后端校验和测试证据；隐藏按钮不能替代后端权限控制。
6. **统一异常**：参数错误、未登录、无权限、数据不存在、业务规则不满足、连接失败、约束冲突和事务失败使用统一错误码/响应格式；前端显示简洁提示，后端日志保留请求标识、时间、操作、角色、错误码和结果。
7. **测试完整**：既有正常流程，也有失败流程；测试结果记录预期值和实际值，覆盖商品、库存、订单、订单明细、角色权限和关键数据库约束。
