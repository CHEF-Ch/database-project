## 四、本周约束与待定事项

1. **对应现有模型**：销售商品为 `item_product`，库存对象为 `item_material` 原料。不能用饮品杯数直接扣原料；调整后现存量须不低于预占量。
2. **避免重复执行**：先核对库存调整、验收、订单扣库与流水的现有服务/DAO，再明确替换清单及提交、回滚责任，不能保留两套同时写入。
3. **保留历史快照**：折扣规则变化不能重算历史订单实际折扣及成交价；先核对字段，再决定是否迁移。
4. **区分过程与函数**：过程承担写业务，函数承担计算查询；各自的非法输入处理须符合 SQL Server 对象限制。

| 待定项 | 需要确定的内容 | 定稿位置 / 时点 |
| --- | --- | --- |
| 销售统计 | 起止日期边界、时间字段、订单状态、退款和优惠分摊、订单去重 | 设计说明 / ① |
| 补货与折扣 | 现存或可用库存、最低/目标库存来源、不存在编号和 NULL 处理、折扣依据及上限 | 设计说明 / ① |

## 五、验收要点

- 对象有参数、返回说明和逐项调用用例，不写死业务编号及日期。
- 日期边界、无销售、非法输入和重复调用均有预期与实际对照；函数结果可人工核对。
- 失败后库存、订单、明细和流水一致，不能仅检查是否报错。
- 应用确实调用数据库对象；受限账户正常操作成功、越权失败，前端不暴露原始异常。
- 他人可按 README 安装、运行和复现；跨人复核通过后再标已完成。
