## 二、验收要点

- 递归脚本包含样例数据、锚点、递归连接和终止逻辑，输出可人工核对的层级路径，并考虑环和递归深度。
- 订单证据覆盖已完成、无明细完成拒绝和支付阶段预占库存不足的回滚。现有支付扣料链路只产生一次库存扣减。
- 补货证据覆盖非正数量、重复入库及库存写入后、单据改状态前注入失败。检查库存、单据和流水均回到初始状态。
- 两个事务分别记录初始值、步骤、预期和实际结果。每轮结束检查 `@@TRANCOUNT`，清理测试事务并重置数据。

## 三、实现与验收

- 递归 CTE 在独立样例中核对了根、中间、叶子及不存在的分类。输出节点数分别为 6、3、1 和 0。
- 订单完成由 `usp_complete_order` 统一写状态和完成时间，沿用第十一周触发器核对金额、明细和扣料证据。支付负责扣料，完成沿用该结果。
- `usp_receive_restock` 从人工录入的待验收单读取原料与数量，按原料号更新库存并写入库流水，全部成功后才更新单据状态。
- [验收结果](../../result/第12周-递归与事务验收.txt)记录独立过程提交、外层事务回滚、后续原料写入失败后的整体回滚、隐式事务模式、重复调用、无明细拒绝和真实 SQL 登录下支付预占不足的回滚。第十三周复用 v2.4 业务入口，双会话按第十三周的基线脚本准备。
