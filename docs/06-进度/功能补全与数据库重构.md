## 一、范围、优先级与状态

- **P0 基础一致性**：必须先于相关维护入口和数据库业务替换完成，不能绕过依赖上线。
- **P1 阶段重点**：本阶段优先纳入，与课程对象、事务和权限验证一起实现。
- **P2 功能补全**：安排在基础链路稳定后，逐项认领，不因为写着“v2.0”就视为已承诺全部完成。
- **条件项**：只完成评估，触发条件满足后再转为实施任务。
- 状态统一为：未开始 / 进行中 / 待复核 / 已完成；暂缓通过“实施决定”记录，不混入状态枚举。负责人未认领时填“待认领”，不根据历史贡献自动分配。

截至建表时，耗用快照、数据库用户表、券审计流水及新数据库对象尚无本表专项验收证据，按未开始管理。顾客账户查询已完成单独提交，见第七节，不重复列为开发待办。
