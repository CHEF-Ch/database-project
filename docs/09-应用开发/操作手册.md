# 第七至九周：操作手册（v1.0）

> 面向演示与验收：从启动、登录，到 5 个角色各自的完整操作链路，以及异常提示与常见问题。
> 结构、调用链与权限矩阵的细节见 [`结构与运行.md`](结构与运行.md)；130 条用例的预期 / 实际见 [`测试用例.md`](测试用例.md)。

## 1. 启动与自检

```powershell
python -m pip install -r requirements.txt
copy .env.example .env        # 演示环境用默认值即可（DB_AUTH=trusted）
python run.py                 # 默认 http://127.0.0.1:5000
```

打开 <http://127.0.0.1:5000/health>，应返回：

```json
{
  "ok": true,
  "database": "MilkTeaShop_v01",
  "auth_mode": "trusted",
  "fingerprint": { "total": 236, "expected_v1_0": 236, "match": true, "...": "..." }
}
```

- `total` 必须是 **236**、`match` 必须是 **true**，否则说明连的不是 v1.0 库（见 `docs/09 §1`）。
- `/health` 不返回服务器地址、账号、密码或连接串；连接失败统一返回 503，明细只写 `logs/app.log`。

## 3. 通用约定

1. **登录**：访问 `/login`，或用首页“登录”按钮；登录后首页显示当前角色、权限点与可用入口。退出走 `/logout`。
2. **页面按钮只是体验控制**：隐藏按钮不等于没有权限；后端 `role_required` 与数据库受限登录会再挡一次，越权统一返回 403。
3. **写操作成功 = 302 重定向**（POST-Redirect-GET，刷新不会重复提交）；失败时：
   - **下单表单**：表单类错误（`E1001` 参数、`E4001` 业务规则、`E3001` 资源不存在、`E5002` 约束冲突）**就地回填**同一张表单，已填内容保留；其余错误（403 / 503 / 500 等）渲染错误页；
   - **商品 / 库存表单**：错误统一交给全局处理器渲染错误页（含错误码与请求标识 `rid`）；
   - 错误页上的 `rid` 与页面底部的请求标识一致，可到 `logs/app.log` 定位。
4. **金额一律服务端重算**：页面上的“券前预估合计”只是 JS 提示，不提交任何金额字段；客户端传金额无效。
5. **每条请求都有 `rid`**：页面底部与错误页可见；排障时用它到 `logs/app.log` 找对应记录。

## 4. 按角色操作

### 4.1 店员 `clerk1`

**① 看商品**：首页 →「商品」→ `/products/`，可按名称搜索、按销售状态筛选；点商品看详情。

**② 现金单（当场结清，直接“已支付”）**：

1. 首页 →「下单」→ `/orders/new`；
2. 在商品表格里填杯数（0 表示不点），选糖度 / 冰量 / 温度，需要时填加料份数；
3. “下单信息”选 **渠道 = 到店**、**下单方式 = 收银台**、**支付方式 = 现金**；会员号可留空；
4. 提交 → 302 到订单详情，状态应为 **已支付**，并生成库存 `SALE` 流水。

**③ 会员 + 优惠券（演示券走 `C0000002`）**：

1. `/orders/new` 顶部“按会员号列券”填 `C0000002` → 查询；
2. 表单里券下拉出现“满 30 减 5”，按杯数选够金额后提交；
3. 提交后详情页的“券前 / 券优惠 / 应付”应为重算后的金额；券状态从未使用变为已用（现金单当场核销）。

**④ 挂单（线上 / 余额，先“待支付”）**：同上，但支付方式选 **线上** 或 **会员余额**；提交后状态为 **待支付**，此时可：

- 在详情页点「确认支付」，选支付方式并填支付流水号（线上必填）→ 状态变 **已支付**；
- 或点「取消订单」→ 预占库存释放、券退回未使用，订单变 **已取消**。

**⑤ 平台单**：渠道选 **外卖平台**，填平台单号、平台、配送地址、配送费（抽成比例可留空取 0.20）；平台单**不预占库存、不积分、会员号留空**，提交即已支付并扣料。

**⑥ 查单**：首页 →「订单」→ `/orders/`，可按状态 / 渠道 / 单号 / 会员号 / 日期范围筛选并翻页。

### 4.2 顾客 `customer1`

1. 首页 →「商品」看菜单（只读）；
2. 首页 →「下单」→ `/orders/new`：渠道与会员号由系统固定（`C0000001`），不能创建平台单、不能指定经办员工或金额；
3. 提交后订单为 **待支付**，页面跳转详情；
4. 在详情页点「确认支付」→ 选 **线上**、填流水号（如 `ON20261103001`）→ 变 **已支付**；
5. 首页 →「我的订单」→ `/orders/mine`：只列出自己的单；直接访问别人的订单号一律 404（行级隔离）。

### 4.3 制作员 `maker1`

1. 首页 →「订单」→ `/orders/`（可用状态筛选找“已支付”的单）；
2. 打开详情 → 点「开始制作」（`PAID → MAKING`）；
3. 再点「完成制作」（`MAKING → COMPLETED`）；
4. 制作员**不能**下单、不能改金额、不能退款；越权操作返回 403。

### 4.4 库存管理员 `stock1`

1. 首页 →「库存」→ `/inventory/`：显示编号、名称、单位、类型、现存、预占、可售、安全库存，可勾选“仅低库存”；
2. **调整库存**：选原料、填增减量（正数入库、负数出库）→ 调整；正数记 `GAIN`、负数记 `SHORT`，与库存更新同事务；
3. **补货**：库存页 →「补货单管理」→ `/inventory/restocks`，填供应商、原料、数量 → 新建（v1.0 一张单只补一种原料）；
4. **验收**：列表中“待验收”的单点「验收」→ 库存增加、写 `IN` 流水；重复验收返回 409，库存与流水不变；
5. **流水**：`/inventory/logs` 可按原料号查库存流水。

### 4.5 店长 `manager1`

1. **商品维护**：首页 →「商品」→「新增商品」`/products/new` 或详情页「编辑」；名称、杯型（`SMALL/MEDIUM/LARGE`）、售价、销售状态；重复（名称, 杯型）由唯一约束拒绝并提示；
2. **退款**：打开已支付 / 制作中 / 已完成的订单 →「整单退款」→ 订单变 **已退款**，冲正积分、回补余额（余额支付）、退回券；**库存不回补**；
3. **看库存**：`/inventory/` 只读（店长没有调库存权限）；
4. **不能下单**：店长没有 `order.create`，`/orders/new` 返回 403——这是“代录归收银员、审核退款归店长”的分工。

## 5. 两条可演示的调用链

**查询链（读）**：

```text
GET /products/ → app/pages/product_routes.py::list_products
  → app/services/product_service.py::list_products
  → app/dao/product.py（参数化 SELECT）→ SQL Server
  → 结果映射 → app/templates/products/list.html
```

**修改链（写，下单）**：

```text
POST /orders/ → order_routes.py::create_order（接参 / 基础校验）
  → order_service.py::create_order（服务端计价、库存充足、加料归属、券门槛）
  → dao.db_cursor("app", commit=True)
      shop_order / order_item / order_item_addon / item_material /
      inv_stock_log / mkt_member_coupon / member_member /
      member_point_log / member_balance_log / order_platform
  → 提交或整体回滚 → 302 到 /orders/<id>
```

## 6. 错误码与提示

| 错误码 | HTTP | 含义 | 页面表现 |
| --- | --- | --- | --- |
| `E1001` | 400 | 参数错误（必填、类型、长度、范围） | 下单表单回填；其余错误页 |
| `E2001` | 401 | 未登录 / 会话失效 | 错误页，提示先登录 |
| `E2002` | 401 | 用户名或密码错误 | 错误页（401） |
| `E2003` | 403 | 当前角色无权 | 错误页 + `rid` |
| `E3001` | 404 | 资源不存在（含别人的订单） | 下单表单回填或错误页（不泄露是否存在） |
| `E3002` | 405 | 请求方式不支持 | 错误页 |
| `E4001` | 409 | 业务规则不满足（库存不足、券不满门槛、状态不可跳） | 下单表单回填；其余错误页 |
| `E5001` | 503 | 数据库不可用 | 错误页“系统暂时无法完成操作” |
| `E5002` | 409 | 约束冲突（如商品重名） | 下单表单回填；商品 / 库存表单走错误页 |
| `E5003` | 500 | 事务失败 / 死锁 / 锁超时 | 错误页“已回滚，请重试” |
| `E9001` | 500 | 内部错误 | 错误页 + `rid` |

## 7. 演示数据注意事项

- **券**：`C0000002` 持有一张“满 30 减 5”的未使用券，适合演示“下单用券 → 取消 → 券回到未使用 → 再用”；`C0000001` 的两张券是 `USED` 与历史 `RETURNED`，不可用。**不要为了演示改 `sql/02-seed.sql`**（会连带 127 行数据指纹与多份证据重跑）。
- **会员**：`customer1` 绑定 `C0000001`；店员代客下单可手填 `C0000002`。
- **重置数据**：演示写入会留在库里。需要干净数据时，按 `README.md`「环境与复现」重建 v0.1 → 复制副本 → `migration.sql`（会重置 `MilkTeaShop_v01`）；执行前先确认没有要保留的数据。
- **自检不污染数据**：`scripts/` 下的测试都在外层事务 / SAVEPOINT 内跑完回滚（并发组用独立沙箱 `MilkTeaShop_test`），跑完 7 单 / 12 明细 / 36 流水不变。

## 8. 常见问题

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| 所有页面 503 | SQL Server 未启动 / 实例名或库名不对 | 查 `.env` 的 `DB_SERVER` / `DB_NAME`，再按 `rid` 看 `logs/app.log` |
| 登录后仍 401 | 会话被清、cookie 被禁 | 重新登录；确认浏览器允许 `127.0.0.1` 的 cookie |
| 操作返回 403 | 当前角色没有该权限点 | 对照 [`结构与运行.md` §8](结构与运行.md) 的矩阵，换对应账号 |
| 打开别人的订单 404 | 顾客行级隔离 | 正常行为，不是缺陷 |
| `/health` 的 `total` 不是 236 | 连到了 v0.1 源库或库被重建 | 确认 `DB_NAME=MilkTeaShop_v01`，必要时重跑迁移 |
| `DB_AUTH=sql` 下大量 403 / 229 | 混合认证未开或 `app_login.sql` 未重跑 | 见 `README.md` 的 `enable-mixed-auth.ps1` + `sql/app_login.sql` |
| 端口 5000 被占用 | 已有实例在跑 | 改 `.env` 的 `APP_PORT`，或用 `Get-NetTCPConnection -LocalPort 5000` 找到进程 |
| 配置项未生效（如 `SECRET_KEY` 仍是默认值） | `.env` 被记事本存成带 BOM 的 UTF-8，首行键名带 `\ufeff` | 另存为 UTF-8（无 BOM）；程序已用 `utf-8-sig` 兜底 |
