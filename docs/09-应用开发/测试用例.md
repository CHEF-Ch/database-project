## 1. 测试范围与优先级

| 范围 | 覆盖内容 |
| --- | --- |
| 认证与会话 | 登录、退出、未登录、会话清理、凭据不泄露 |
| 权限与越权 | 5 个角色 × 权限点；页面隐藏按钮 + 后端二次校验；水平越权/IDOR |
| 商品 | 查询、筛选、店长维护、重复/非法值、注入 |
| 库存与补货 | 查询、调整、流水、补货创建/验收、负库存/预占约束 |
| 订单与事务 | 到店现金、自助待支付、平台单、支付、取消、退款、制作状态 |
| 查询与统计 | 订单明细、销量视图、低库存、日期筛选、分页 |
| 异常与安全 | 400/401/403/404/405/409/500/503；错误码分类；SQL/堆栈/连接信息不泄露 |
| 数据库一致性 | 指纹 236、金额等式、预占/流水、会员快照、约束启用、无孤儿行 |
| 并发/幂等/故障 | 末件库存、重复支付、重复取消、订单号碰撞、故障注入回滚 |
| 复现与交付 | 空库复现、启动、`/health`、演示账号、README 命令、证据脱敏 |

**优先级**：

- **P0**：阻断交付。认证、核心权限、下单事务、原子性、错误信息不泄露。
- **P1**：主要功能与验收项。商品/库存/订单页面、退款、补货、查询、异常分类。
- **P2**：边界与加固。并发、幂等、注入、XSS、分页边界、性能观察。

**不在本阶段范围**：v2.0 的 RLS/触发器、部分退款、真实支付网关、压力测试、多实例部署。

## 3. 错误码与响应约定

| HTTP | 错误码 | 含义 | 典型场景 |
| --- | --- | --- | --- |
| 400 | `E1001` | 参数错误 | 必填缺失、类型/长度/范围不合法 |
| 401 | `E2001` | 未登录 | 访问受保护页面 |
| 401 | `E2002` | 凭据错误 | 用户名或密码错误 |
| 403 | `E2003` | 无权限 | 角色越权、数据库 229/230 |
| 404 | `E3001` | 资源不存在 | 商品/订单不存在、未知路径 |
| 405 | `E3002` | 方法不允许 | GET 路由用 POST |
| 409 | `E4001` | 业务规则不满足 | 库存不足、状态不可跳转、券不可用 |
| 409 | `E5002` | 数据库约束冲突 | 2627/2601/547/515 等 |
| 500 | `E5003` | 事务失败 | 事务提交/回滚异常 |
| 500 | `E9001` | 未预期异常 | 代码异常；前端只看到通用提示 |
| 503 | `E5001` | 数据库不可用 | 连接失败、库不存在、登录失败 |

**响应断言**：

- JSON 响应必须含 `ok`、`code`、`message`；不得含 SQL、堆栈、库名、驱动、服务器、账号、密码。
- HTML 错误页只显示错误码、通用提示、`request_id`；详情只进 `logs/app.log`。
- 页面/JSON 的 `message` 必须是面向用户的中文提示，不是原始异常文本。

## 7. 执行记录模板

执行时在 `result/` 新建证据文件，例如 `result/第8周-⑦集成测试-YYYYMMDD.txt`，按下面格式记录：

```text
用例 ID | 预期 | 实际 | 结果(PASS/FAIL) | 证据/备注
AUTH-01 | 200  | 200  | PASS           | 页面含 5 个账号
ORD-14  | 409  | 409  | PASS           | 无订单/流水残留
...
总计：N 项，PASS N，FAIL 0
```

**失败处理**：

- P0 失败：阻断交付，修复后全量重跑。
- P1 失败：记录缺陷、影响范围、临时规避；修复后重跑相关组。
- P2 失败：记入已知限制，明确是否影响验收。
