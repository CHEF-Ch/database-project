# 账户展示与页面入口检查（2026-11-17）

## 本次新增

顾客导航“我的账户”（GET /account）展示当前积分、储值余额、积分流水和储值流水。流水按时间与唯一流水号倒序，各自每页20条，可跳转关联订单；没有流水时展示空态。

身份只取session.member_id，不接收请求中的会员号；未登录401，非顾客403，未绑定会员409。查询使用顾客连接，所有流水SQL带会员过滤条件，不依赖隐藏按钮。现有order.read_own作为登录权限门槛，业务层进一步限定customer，不新增权限点。

SQL认证新环境由sql/app_login.sql授权；已有v1.0环境运行sql/account_read.sql。本机已执行后者，只增加两张流水表的SELECT权限，不修改表结构、积分、余额或业务流水。数据库角色不提供会员RLS，逐会员过滤由应用保证。

## 验证

- scripts/account_pages_test.py：6项通过，覆盖登录、员工拒绝、未绑定、非法分页、请求伪造会员号、流水分页与SQL参数。采用模拟数据验证路由与查询契约。
- 实际Windows认证账户页返回200；数据库EXECUTE AS USER=login_customer可读取两类流水。
- 本机缺DB_PWD_LOGIN_CUSTOMER，完整SQL登录账户页尚未验证，不将用户模拟等同于SQL登录成功。

## 类似入口缺口

| 项目 | 当前实现 | 处置 |
|---|---|---|
| 充值 | 数据表、样例充值流水、余额增量DAO；没有充值业务页面与完整充值流程 | 记录待办；不能将余额消费已实现等同于充值入口已实现 |
| 发券/领券 | 预置会员持券；有锁定、核销、退回；coupon.write尚未接页面 | 已有下一版安排，本轮不扩展 |
| 临期与统计报表 | 视图、report DAO存在，前端入口缺失 | 统计入口已有下一版安排；临期提醒展示也应一起补齐 |
| 配方/加料维护 | 只读展示存在，维护页面缺失 | 已有下一版安排，依赖耗用快照与待付款保护 |

本轮补的是已有会员交易数据的查询展示，不增加充值、积分兑换或券发放操作。
